# 冰湖小队

原创二维网页钓鱼竞赛，**本地试玩**：暖橘小队为你和电脑队友「松果」，霜蓝小队为两名电脑「阿岚」「小凛」。没有账号、后端或在线玩家。角色、雪杉林、冰镜湖、霜石岭、帐篷、钓具及物品均为代码绘制的原创卡通图形，不使用《饥荒》素材、文件或接口。

## 启动与检查

需要 Node.js 20.19+ 或 22.12+（本次实际使用 24.19.0）、npm。

```sh
npm ci
npm run dev
```

在电脑浏览器打开终端输出的本地地址，点击「开始比赛」开始。正式限时赛默认 **20 分钟**；可以选目标积分赛，自定目标；「2 分钟短局」是独立测试选项。

```sh
npm run build       # TypeScript 检查与生产构建，输出 dist/
npm run preview     # 本地预览生产构建
npm test            # 仿真规则测试
npm run test:browser # Chromium 完整流程与截图检查
```

浏览器测试默认使用 `/usr/bin/chromium`；其他机器设置 `CHROMIUM_PATH=/你的/浏览器路径 npm run test:browser`。也可 `npx playwright install chromium` 安装 Playwright 浏览器后，将 `CHROMIUM_PATH` 设置为该浏览器实际路径。网页正常运行不需要安装 Playwright 浏览器。

## GitHub Pages 发布

仓库提供 [自动部署工作流](.github/workflows/deploy-pages.yml)。在仓库 **Settings → Pages → Build and deployment** 中，将 **Source** 设为 **GitHub Actions**。首次启用需要有仓库 Pages 管理权限；工作流使用的默认 `GITHUB_TOKEN` 不负责首次开启站点，无需为工作流另外添加个人令牌。

之后推送到 `main` 会自动安装锁定依赖、执行规则测试、按 `/ice-fishing/` 路径构建并部署 `dist/`。也可以在 **Actions → Deploy game to GitHub Pages → Run workflow** 手动重新发布。工作流使用 GitHub 官方 Actions 并固定完整提交 SHA；部署只授予 Pages 写入和 OIDC 令牌权限。

预期站点地址为 `https://sci233.github.io/ice-fishing/`；只有工作流部署成功且网址实际可访问后，才表示已经上线。

本地验证发布构建：

```sh
npm run build -- --base=/ice-fishing/
npm run preview -- --base=/ice-fishing/
```

预览时打开终端显示地址下的 `/ice-fishing/` 路径。根路径开发仍使用 `npm run dev`，无需改变日常开发地址。公开网站同样是本地试玩规则，电脑角色不会变成在线玩家。

## 怎么玩

- **WASD / 方向键**移动。走到冰面，**E**用开局破冰镐开洞，再按 **E** 抛竿。
- 等咬钩后，标记会在钓鱼条移动；进入金色成功区时按 **空格**。成功立即给队伍计分，物品保留在个人背包；失败不扣已有积分。
- 移动或 **Esc** 取消钓鱼，钓洞会释放。其他队伍也可以使用空洞；有人占用时不可抢占。
- 靠近可采集的树或矿石按 **E**，短暂等待后获得材料；移动取消。采集不计比赛积分，资源耗尽后自动恢复。
- **B** 或界面按钮打开背包、营地与队友分工；菜单期间地图键不会穿透，**比赛仍继续**。靠近本队篝火按 **E** 也能打开营地。
- 消耗木材给本队木制篝火添燃料，回到燃烧的篝火附近恢复保暖与生命。持续寒冷先降低保暖，保暖耗尽后损失生命。
- 在本队营地消耗 **4 木材、3 矿石**升级为「暖星钓竿」：成功区从 24% 扩大到 40%，优质鱼概率提高。材料是真实消耗，每根竿只升级一次。
- 鱼可以在背包中使用，恢复生命和少量保暖。使用、交付材料、复活都不会再次计分。
- 松果可切换「主要钓鱼／主要采集」；采集时会实际移动、采集、补给，并把材料交给你。电脑会在低保暖时回营、燃料不足时采木添柴；也使用真实装备、物品与失温规则。
- 不可攻击角色。死亡保留得分和背包；每名角色分别按第 1／2／3 次及以后死亡等待 **10／20／30 秒**，然后在本队营地恢复生命与保暖，并获得 12 秒御寒保护。
- 限时赛结束分数最高者赢；平分进入最多 60 秒加时，取得领先立即获胜，仍平分则共同获胜。目标积分赛在首次达到目标时结束。
- 结束后行动与计分冻结。结果界面可以再玩一局或返回选择规则；新局清空上一局分数、物品、洞、死亡次数与时间。

## 测试入口

在地址后加 `?debug=1`，显示「测试工具」：本局缩至 10 秒、强制平分并进入加时、触发玩家死亡、给予 6 木材和 4 矿石。正常页面隐藏这些入口。

测试模式还提供 `window.__ICE_TEST__`（正常页面不创建）：

```js
__ICE_TEST__.snapshot()       // 当前可序列化状态
__ICE_TEST__.advance(10)      // 分小步推进规则，用于死亡/复活/计时检查
__ICE_TEST__.sim.debug('tie') // 与界面按钮同一规则入口
```

自动化会使用测试模式布置位置和时间，随后通过实际键盘与菜单完成交互。测试证据输出到 `test-results/`，完整检查结果见 [VALIDATION.md](VALIDATION.md)。

## 暂定平衡数值

统一配置在 [`src/game/config.ts`](src/game/config.ts)，**这些是试玩初值，尚未经过平衡验证**。等待咬钩 2.2–4.8 秒；电脑收竿成功率基础 70%、升级 84%；采集每次 2 单位、1.3 秒；开局篝火 95 秒燃料，1 木材补 32 秒；野外保暖每秒下降 0.72、篝火旁每秒恢复 9、严重失温每秒扣 6 生命。

| 钓获 | 积分 | 基础概率 | 升级概率 |
|---|---:|---:|---:|
| 雪银鱼 | 6 | 52% | 30% |
| 绯尾鱼 | 12 | 20% | 32% |
| 月灯鱼 | 25 | 5% | 18% |
| 漂流木（可作木材） | 2 | 14% | 12% |
| 冰纹矿石 | 3 | 9% | 8% |

这里只在钓鱼成功的事件中计分；相同木材或矿石来自采集时不计分。鱼使用后恢复 18 生命与 8 保暖，不引入饥饿、烹饪或疾病。

## 模块与版本

- `src/game/types.ts`：纯数据契约。
- `config.ts`：玩法暂定值与地图对称坐标。
- `Simulation.ts`：移动、交互、物品、营地与生存，作为本地唯一状态来源。
- `fishing.ts`：成功区、浮标运动与按装备加权随机钓获。
- `rules.ts`：目标分、限时、加时与冻结结算。
- `ai.ts`：电脑目标选择，调用与玩家共享的行动规则；不直接发积分。
- `src/view/`：Phaser 场景与原创矢量画面，适配仿真状态。
- `src/ui/`：中文 HTML/CSS HUD、菜单、结果、测试工具。
- `src/main.ts`：仿真、画面与菜单的连接；仅在明确测试模式暴露测试 API。

实际依赖固定为 Phaser **3.90.0**、TypeScript **5.9.3**、Vite **7.1.7**，测试工具 Vitest **3.2.4**、Playwright **1.55.1**；`package-lock.json` 固定传递依赖。核对采用版本的官方资料：

- [Phaser 3.90.0 官方 README](https://github.com/phaserjs/phaser/blob/v3.90.0/README.md) 与 [Scene 官方 API 源码注释](https://github.com/phaserjs/phaser/blob/v3.90.0/src/scene/Scene.js)
- [Vite 7.1.7 官方入门文档](https://github.com/vitejs/vite/blob/v7.1.7/docs/guide/index.md)
- [TypeScript 5.9.3 官方文档入口](https://github.com/microsoft/TypeScript/blob/v5.9.3/README.md)

官方独立文档站在当前云网络中返回 403，所以本次读取上述对应版本的官方 GitHub 文档与安装包的类型定义。

## 已知限制与后续

本次固定两队各两人，单人本地操作，其余是明确标注的电脑。电脑采用简单目标选择、圆形碰撞与小网格绕障，不具备复杂寻路、战术协作；菜单不暂停比赛；极低帧率或切换后台时仿真时间可能比墙上时钟慢。只支持电脑键盘操作，没有手机触摸方案、声音或复杂高度。原创矢量素材是首版美术，未使用外部字体和资源服务。

未实现真实联网/房间/自由编队、赛前物资点采购、更多渔具、卡片、盲盒、营地商人、狩猎陷阱、岸钓、造船或海洋玩法，也没有用于展示这些功能的假按钮。独立仿真边界便于后续由服务器接管状态，但当前不承诺联网一致性或反作弊。
